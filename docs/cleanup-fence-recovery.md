# 未确认布局清理的不重启恢复

日期：2026-11-02。恢复事务、保留目录登记、CLI 及 CI 核验已接入；平板真实阻塞会话已通过正式入口恢复。

主机 shell 与平板原型实测确认了一条有限路径：先占住旧命令必须创建的专属目录，可以阻止尚未进入执行阶段的旧命令。新入口 `harmonyos-cleanup-recovery` 将这一步接入恢复事务，按原清单清理图片文件，并保留阻挡目录。新会话及 CI 会核验回执和保留清单。

下文分别记录第一轮原型和正式入口的验证，均不计入 UI 用例稳定性统计。

## 正式入口

```powershell
& $cli --platform harmonyos --device $device harmonyos-cleanup-recovery `
  --session $originalSession --hdc $hdc --original-cli $originalCliDirectory
```

`$cli` 使用新构建的完整分发包；`$originalCliDirectory` 指向产生旧会话的原分发目录，内部应有 `lib`。入口不启动应用、不录屏、不重启系统。同一命令可续办已登记事务，但必须继续使用原工具集；不要覆盖用于恢复的分发目录。

旧日志没有保存包装器版本，因此初版只接受已完成 shell 竞争验证的恢复日志类指纹，名称为 `exclusive-operation-mkdir-v1`。指纹不匹配会在设备派发前拒绝，不能仅凭版本号相同跳过检查。调用者仍需确认指定目录确实是原会话使用的分发包；类指纹不是发布者签名，也不能建立任意历史会话与分发包之间的关联。

成功输出为 `maestro.harmonyos.cleanup-fence-recovery` v1，包含 `state=isolated`、`handoffReady=true`、`originalResult=unknown` 及版本 4 回执的路径和摘要。含义是旧清理已被隔离、设备允许新会话；不是原用例通过，也不是所有旧目录已删除。CLI 返回非零或没有完整回执时继续保留隔离。

完整字段、成功与阻塞示例及 JSON Schema 见[清理隔离格式](protocol/cleanup-fence.md)。结构检查不能代替身份、证据链和设备目录核验。

占用记录使用版本 3，包含 `cleanupFence` 和 `retainedFences`。后续普通会话保留这份清单，并在取得设备锁后、打开驱动前重新检查设备上的阻挡目录。旧 CLI 拒绝版本 3；普通 `agent.recover` 和顺序重启维护也不会接管正在进行的清理恢复。

恢复命令使用独立调用日志，原会话日志和原回执保持原字节。完成前保留完整阶段链、每次调用的参数摘要、原始应答和本机进程终态。目录创建或图片清理应答丢失时，续办只发送固定核验命令；取得匹配本事务的远端标记后才继续。清理标记缺失时不重放删除。

如果互斥目录创建明确返回“已被占用”，且主机调用已结束，入口保存拒绝凭据并恢复原隔离记录。此时可以再用普通恢复检查旧命令的完成文件。若创建目录后、写归属标记前中断，仍保持未知；不能认领空目录。

### CI 与客户端

保存 CLI 完整 JSON 后，现有 `scripts/ci/run-device-suite.ps1 -ReconcileOnly -RecoveryReportPath <文件>` 可以核销外层占用。核验要求旧 CI 主机及执行进程已结束，再校验恢复链；原 `execution` 和失败结果不变。

Node 调用方使用 [`verifyCleanupFenceReport`](../examples/agent-client/cleanup-fence.mjs)，显式提供 `deviceId`、可信 `recoveryRoot`、原作业 `createdAt` 和保存的 `responsePath`。它只读核验磁盘证据；真正开始下一次会话时，CLI 还要重新检查设备上的目录。CI 冻结计划包含核验器及固定命令生成模块的摘要。

CI 归档收集与原回执绑定的完整恢复链，后续更换当前会话不影响归档。带有保留目录的后续普通会话，也会将其清单带入 CI 核验结果和归档。

## 本次问题为何适合调查这条路径

平板断连后的普通恢复已经找回部分完成凭据，剩下 1 条未确认命令。参数摘要唯一匹配本会话登记的一份布局文件的 `rm -f`。全部主机调用已记录结束，日志已封存，没有录屏资源或驱动关闭错误。

只读检查曾发现该操作目录不存在、目标布局仍存在。这只能说明读取当时的状态，不能证明旧请求已从 HDC 队列消失。因此，目录不存在、进程不存在、重新插入 USB，都不是本方案的释放依据。

## 阻止旧命令的依据

现有 `HarmonyOSRecoveryJournal` 生成的设备 shell 包装器按以下顺序执行，省略了父目录检查与完成凭据写入：

```sh
mkdir "$session_root/$operation_id" || exit 119
# 只有 mkdir 成功才会进入原命令
rm -f "$registered_layout"
```

恢复原型也尝试创建同一个操作目录。它不先用 `test -e` 判断是否可接管，而是以 `mkdir` 本身的成功或失败决定结果。

| 竞争结果 | 旧命令 | 恢复流程 |
| --- | --- | --- |
| 恢复先创建目录 | 在执行原命令前退出 119 | 可以取得“已阻止本次派发”的证据 |
| 旧命令先创建目录 | 可能已经执行或正在执行 | 创建失败，拒绝接管；仍走原完成凭据检查 |
| 目录早已存在，但归属不明 | 无法从目录存在推断执行结果 | 拒绝认领 |
| 恢复创建目录后，在写标记前中断 | 旧命令仍被目录阻挡 | 缺少归属证据，保持未知 |

这样证明的是旧包装器无法跨过执行入口，而不是证明旧请求已结束或已从队列移除。必须保留操作目录及其父目录：删除它后，同一旧包装器可以再次创建目录并执行。负向对照已经验证这一点。

此结论还依赖同一设备、同一个会话根目录、同一个操作 ID，以及产生旧命令的包装器确实具有上述顺序。仅有相同命令文本或相似文件名不足以使用本方法。

## 已完成的验证

可复现原型为 [`CleanupFenceProbe.java`](../scripts/tests/fixtures/CleanupFenceProbe.java)。它通过真实 `HdcClient` 和恢复日志生成包装器，再在 shell 执行；没有手工另写一个简化版来代替旧命令。主机执行仅替换临时根路径，设备执行保留生成的完整路径与包装器。

| 验证 | 主机 | 平板 |
| --- | --- | --- |
| 恢复先占目录，多次迟到的旧包装器均被拒绝 | 通过 | 通过 |
| 保留旧阻挡目录时，另一代独立目录可执行清理命令 | 通过 | 通过 |
| 原命令先执行，恢复拒绝认领其目录 | 通过 | 通过 |
| 创建目录后、写标记前注入失败，重试保持拒绝 | 通过 | 通过 |
| 删除阻挡目录后，旧包装器重新执行成功的负向对照 | 通过 | 通过 |
| 双方同时派发竞争 | 20 次通过 | 4 次通过 |
| 操作路径或 `files` 父目录为符号链接时拒绝执行 | 未在 Windows 模拟链接 | 2 项通过 |

前两项在同一场景内验证。主机总计 24 个场景；平板总计 10 个场景，两种竞争赢家均有实测结果。主机另用产生真实阻塞会话的原冻结 CLI 完成相同 24 项检查；冻结文件在运行前核对了 SHA-256。以上轮次是恢复机制测试，不是 UI 稳定性统计。

平板测试持有正常会话使用的同一个设备锁。测试前后核对真实占用文件和恢复日志的字节，确认未变化。测试使用随机新目录，不进入真实旧会话根目录；每条设备命令都校验独立的退出状态凭据，不能只看 HDC 的退出码。

首次平板探针因输出带回车符，未通过 `FENCED` 字符串比较。设备已返回成功；探针保留现场后修正了比较，再用全新目录完成测试。首次探针的独立目录在核对两条命令均已返回、内容和归属一致后定向清理。没有将这次失败计为通过。

“写标记前失败”是受控 shell 故障注入，不是实际主机崩溃或 USB 断连测试。独立新目录的命令成功，也不代表正式 `begin`、YAML 执行及 `release` 已经通过这条恢复路径。

## 首版接入范围

首版只支持以下全部条件同时成立的会话，复用现有日志、设备锁和主机进程终态检查：

1. 同一主机的原设备占用处于隔离状态；设备、owner、generation、日志路径及摘要绑定一致。没有运行中的其他恢复流程或重启维护检查点。
2. 日志已经封存，主机调用全部确认结束，没有未落盘状态、录屏资源或驱动关闭错误。
3. 恰好一条未确认操作，其余操作已经取得有效完成凭据；未确认操作声明为有限命令。
4. 用原实现的参数序列化方式重新计算摘要，唯一匹配 `rm -f <已登记的 layout-UUID.json>`。首版不接受递归删除、目录删除、通配符、多路径或任意 shell 文本。
5. 其余登记资源仅为本会话的布局 JSON、截图 PNG。不能借此认领文件名相似但未登记的内容。
6. 原构建来源可以核对，旧包装器确实在执行原命令前独占创建操作目录。不能用新 CLI 的行为推断来源不明的旧 CLI。
7. 设备路径检查没有符号链接、同名普通文件或未预期内容。恢复实际创建操作目录成功，且归属标记与本机恢复意图匹配。

为限制单次恢复范围，初版接受 1～16 条原操作、1～16 个登记图片路径，生成的 shell 命令不超过 6 KiB。一次事务最多登记 64 次调用，单设备最多保留 8 个恢复目录；超过范围会拒绝。设备调用共享 30 秒预算，原 HDC 进程收尾规则继续适用。

这不覆盖点击、输入、应用生命周期、未确认录屏，也不处理任意数量的 pending 操作。任何一项不成立，继续保留隔离状态，不能退回“文件看起来没了就算结束”。

## 恢复事务

清理恢复使用独立入口，不改变现有 `agent.recover` 对完成凭据的判断。

| 阶段 | 必须保存的证据 | 中断后的处理 |
| --- | --- | --- |
| 登记恢复意图 | 原 gate、日志、构建摘要；设备、owner、generation、操作 ID、命令摘要；新恢复 ID 与随机标记 | 原子落盘后才允许发送设备命令；记录缺失时不派发 |
| 创建阻挡目录 | 互斥 `mkdir` 成功；随后写入绑定上述身份的标记并原子改名；保存原始应答 | 创建失败不接管；应答丢失时只能核对本机意图及完整远端标记，不能认领任意空目录 |
| 核验并清理图片资源 | 保留根目录、`files` 目录和阻挡目录；只对原清单里的精确文件操作，记录每次调用和结果 | 清理应答未知、出现额外文件或同名目录时继续隔离 |
| 写入恢复回执 | 原命令仍为未确认；新增 `prevented_before_dispatch` 处置、保留目录清单和资源清理证据 | 原回执和日志不覆盖；回执落盘失败不交接 |
| 允许新一代会话 | 核验回执及保留目录；新 owner 和 generation 使用独立根目录 | 每次取得设备锁后重新核对，不复用旧根目录 |

创建目录成功、写标记前崩溃时，初版继续拒绝自动恢复。即使这个空目录实际已挡住旧命令，也不能在重试时假定它就是本流程创建的。完整标记已写入但主机没收到应答时，可按保存的恢复意图核验标记；这与认领任意现有目录不同。

原 `completed=false`、原错误及原测试结果保持不变；“阻止派发”不是执行成功。也不能把 `rootRemoved` 写为 true，因为根目录必须保留。临时资源已清理、设备可交接、旧命令已结束是不同结论，报告必须分别表达。

### 保留目录如何管理

保留目录进入跨会话的持久清单，绑定设备、原代际、操作 ID、原始证据和恢复回执。保留的范围包括根目录、`files` 目录、阻挡目录及已经完成操作的凭据目录；登记的图片文件按精确路径删除。新会话不能覆盖清单；普通关闭、普通恢复不能删除这些目录。每次取得新会话前都核验它们，缺失或被修改则阻止自动运行。

当前实现还未提供保留目录回收。等待一段时间、找不到进程或下一次用例成功，都不能作为删除依据。以后只有取得能排除旧派发的独立证据，才能通过专门的回收流程删除。原顺序重启维护可作为候选回收方式，但需要扩展证据核验，不能直接套用当前维护实现。

本方案针对现有单主机、共享设备状态目录的模型。另一台主机接管同一设备、人工清扫临时目录、系统自动清理这些目录等情况尚未验证。下一次会话开始前会检查目录完整性；本机制不能约束任意外部进程删除它们。

### CLI、客户端和 CI 的衔接

占用记录使用版本 3，清理隔离回执使用版本 4。产生原阻塞会话的旧 CLI 已实测拒绝新占用记录；普通恢复和重启维护也拒绝接管正在进行的清理恢复。

Node 核验器及 PowerShell CI 核销入口校验同一条证据链，区分“已隔离旧派发且允许新会话”和“所有临时目录已删除”。归档保存原日志、恢复意图、设备应答、保留目录清单及回执；后续新会话不影响旧运行归档。主机联测覆盖核销成功、证据错误时继续占用，以及后续普通会话继承目录凭据的归档。

## 复现原型

使用本仓库构建且包含恢复日志与持久设备锁的完整 CLI 分发目录，JDK 17。输出目录必须不存在，父目录需要预先创建。下面是参数形式，工具路径按实际环境填写：

```powershell
# 主机：Windows 下使用 Git Bash；不连接设备。
& $java --class-path "$cli/lib/*" scripts/tests/fixtures/CleanupFenceProbe.java `
  host .local/probe-host $bash

# 平板：仅独立文件系统测试；要求真实占用已经隔离且未进入维护。
& $java --class-path "$cli/lib/*" scripts/tests/fixtures/CleanupFenceProbe.java `
  device .local/probe-device $hdc $device
```

设备模式会在 `/data/local/tmp` 新建随机测试目录并执行定向文件操作，必须在已安排的专用测试设备上运行。它不会恢复真实会话。失败时保留探针目录和记录，先核对所有已派发命令的终态，再清理明确归属的探针路径，不扫描或递归删除会话目录。

成功摘要必须同时看到 `passed=true`、`prototypeOnly=true`、`actualSessionReleased=false`。原始设备标识、脚本、布局信息及逐条应答保存在本地忽略目录，公开文档仅记录范围与结果。
