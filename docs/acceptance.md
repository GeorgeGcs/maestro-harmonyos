# 验收计划

更新日期：2026-10-29。当前为工程验证记录与验收计划，尚无活动验收结果。部分功能已在一台真机验证；官方示例、20 轮稳定性、跨设备兼容和 VSCode 扩展仍未完成。

## 活动要求与待确认事项

以[课题 11 交付要求](https://atomgit.com/harmony-connect/topic-details-and-delivery#topic-11)及活动组后续公开答疑为依据：标准 Maestro YAML 覆盖约定的鸿蒙官方示例典型交互场景，重复执行 20 次通过率不低于 95%，开源并提供使用文档与开发指南。核心交付还包含 Flow 编排、容错重试、视频录屏、批量执行与标准报告，以及 VSCode 编辑和操作录制辅助。

正式运行前，需要明确并记录：

| 项目 | 待确认内容 |
| --- | --- |
| 官方示例 | 仓库、固定提交/版本、应用包、页面和典型场景清单 |
| 测试环境 | 设备型号、系统版本、SDK/UITest/HDC 版本和宿主机环境 |
| 命令边界 | 必须覆盖的标准命令、选择器、参数化、条件及 JavaScript 场景 |
| 重复运行 | 20 次针对每个 Flow 还是完整套件；成功率的分母与重试口径 |
| 初始状态 | 每轮应用数据、权限、登录态、语言、网络和页面的准备方法 |
| 操作录制辅助 | 是否接受截图/节点点选后执行并插入 YAML，是否要求设备侧手工操作捕获 |
| 留证方式 | 视频格式、报告格式、失败材料、日志和测试记录的提交形式 |

不额外将应用市场上架、上游 PR 合入或未约定的系统版本设为活动验收硬门槛。本文中的测试清单是工程验证计划，最终验收范围以双方确认内容为准。

视频录屏为实验性功能，默认关闭。须显式设置 `MAESTRO_HARMONYOS_RECORDING=huawei-system`，依赖目标设备的 Huawei 系统录屏服务和媒体工具，测试期间必须独占录屏。它与 VSCode 操作生成 YAML 是两项能力；录屏接入不代表 A10 完成。

本轮录屏实测：

- 正常 `recording-smoke`：CLI 退出码 0；MP4 为 11,118,966 字节、39.04 秒、890 × 1920，FFmpeg 严格全帧解码 2,227 帧通过。
- 故意执行 `assertTrue: false` 的首次失败流程：CLI 退出码 1，原断言错误保留；自动停止录屏并导出 3,160,515 字节、12.12 秒的视频，检查到录屏进程和临时文件均无残留。但严格解码在约 620 帧处出现尾部 H.264 `mmco/unref` 错误，同一文件的单线程和双线程解码均复现，不将该视频记为完整可播放。
- 同一失败流程原样复跑：CLI 仍返回 1，导出 3,184,843 字节的视频，严格全帧解码 630 帧通过。首次产物和错误记录保留，不用复跑结果覆盖。失败流程的自动收尾已验证，短视频偶发尾部解码错误的原因尚未查明。

## 20 轮统计方法

每个正式验收单元采用事先固定的场景、脚本、版本和初始状态，运行编号为 `01` 至 `20`。在活动组明确验收单元前，同时保留逐 Flow 结果和整套结果，避免只用总平均值掩盖某个 Flow 的失败。

- **原始通过率** = 首次执行通过的轮数 ÷ 20。该轮发生执行失败、需要额外重跑或人工修正时，原始结果记为失败；预先声明的正常状态等待不等于失败重试。
- **重试后通过率** = 在预先固定的重试策略内最终通过的轮数 ÷ 20。记录每次尝试、触发原因、重试上限和恢复过程。
- 20 轮中 19 轮通过等于 95%。活动最终采用哪一项成功率由验收口径确认，报告必须同时展示两项，不能以重试后的结果替换原始失败。
- 断连、准备失败、运行中断和工具崩溃均保留原始记录。正式轮次的排除或补跑必须注明原因和依据，不能静默删除失败轮次。
- 运行中修改驱动、脚本、重试策略或依赖版本后，按新版本重新建立 20 轮记录，不混合不同版本的结果。

建议每轮至少记录：运行编号、场景/Flow、版本标识、设备与环境、开始/结束时间、首次结果、尝试次数、最终结果、失败步骤与原因、日志/布局树/截图/视频/报告路径、是否人工介入。

## 交付材料

- 可复现构建的适配源码、固定上游基线和依赖说明。
- 标准 YAML 用例、官方示例来源、场景与命令覆盖矩阵。

- 使用说明、开发指南、支持范围、已知限制和问题记录。
- 第三方许可证与依赖清单、AI 生成内容披露及相应审查验证记录。

每项材料随实现更新；未完成项继续标为待完成，不以设计文档、模拟数据或一次演示代替真机执行证据。
