# 录屏检查与恢复

Huawei 系统录屏后端仍为实验功能，使用前先看[环境配置](setup.md#视频录屏)。MP4 能打开、有视频轨，不代表每一帧都能解码。录屏质量与设备是否已释放分别判断：视频损坏会使证据检查失败；设备清理完成也不能把损坏视频算作有效材料。

完整长场景可参考 [HMOS 分段录屏入口](../examples/hmos-code-lab/flows/recorded-suite/README.md)。单段默认上限 180 秒，`MAESTRO_HARMONYOS_RECORDING_MAX_SECONDS` 只接受 1～600；该入口按输入、按钮和弹窗分成三段，设置单段 600 秒、runner 总预算 1800 秒。段间没有应用 UI 操作，但停录、导出与重新启动存在间隔；达到上限会失败，不自动续录。每段使用唯一名称，并分别收集诊断、核对场景覆盖和完整解码，不能用一段通过代表整个 Flow 的录像有效。

## 收集阶段诊断

系统录屏后端会把启停、采集结束、导出、接收、归档和清理的观察写入 Flow 日志。执行结束后，可以从原 attempt 收集独立报告：

```powershell
node scripts/collect-recording-diagnostics.mjs `
  --result '<agent-root>/runs/<runId>/<attemptId>/result.json' `
  --output-directory './artifacts/recording-diagnosis-01'
```

输出目录必须尚不存在且位于原 attempt 之外。报告按明确的录制上下文和输出路径关联视频，核对原结果、索引、清单及引用文件的哈希；缺事件、丢日志或同一路径被多段录制使用时会标为不完整。旧版本没有阶段日志，不能事后补齐这些观察。字段、限额及退出码见[诊断报告格式](protocol/recording-diagnostics.md)。

诊断报告保留原执行错误与清理状态。`complete` 只说明诊断材料完整，不代表视频解码通过或设备可交接；仍需分别完成下述检查。阶段时间来自主机观察，归档哈希来自已登记的元数据，均不替代独立复核。日志和报告可能包含本机路径、媒体 URI 及原错误详情，公开分享前应检查内容。

拉取正常返回后，录屏后端会在同一收尾预算内再次读取同一远端文件的大小。前后大小与本地长度不一致时，停止校验和输出，保留手机媒体；拉取本身抛错时不追加查询。诊断报告分别记录两次观察，旧日志或查询失败仍为 `not_observed`，不会从本地长度补填。大小一致只能说明长度未变，不能排除同长度内容变化或码流损坏。

## 完整解码

仓库不附带或自动下载 FFmpeg。准备可执行文件后，从仓库根目录运行：

```powershell
./scripts/verify-recording.ps1 `
  -InputPath './artifacts/run/startRecording/input-recording.mp4' `
  -FfmpegPath 'C:/tools/ffmpeg/bin/ffmpeg.exe' `
  -OutputDirectory './artifacts/video-checks' `
  -TimeoutSeconds 180
```

工具创建独立目录，保存 `verification.json`、解码器标准输出和错误输出。它选择第一条视频轨，完整解码到空输出，不转码、不修改输入。通过条件是 FFmpeg 返回 0、没有 error 级诊断、收到解码结束标记、至少解出一帧，并且检查前后的输入 SHA-256 一致。音轨不在本工具的检查范围内。

自动化调用可额外传 `-ReportPointerPath '<已存在的父目录>/decode-pointer.json'`，明确取得本次报告路径和 SHA-256，无需从控制台文字或最新目录猜测。指针文件必须尚不存在，路径不得经过链接，也不能与输入或解码器重合。报告封存后写入指针，解码失败同样保留指针和失败报告；强制结束进程或写入失败则不保证存在指针。读取方仍须核对原报告、输入身份和实际退出码，不能把指针存在当作通过。

报告记录输入哈希、FFmpeg 路径及哈希、版本、实际命令参数、帧数、退出码与超时事实。版本探测最多 10 秒，解码使用指定期限；超时后只终止本工具启动的进程并有限等待。每路日志最多保留 1 MiB 字符，输出超过上限同样失败。退出码 0 表示检查通过，其他结果保留报告后返回非零。文件系统读取本身仍依赖操作系统响应，不能保证损坏磁盘上的每次读操作立即返回。

资源登记、内部恢复凭据和解码结果的字段及 Schema 见[录屏文件格式](protocol/recording-resources.md)。结构检查之后仍需读取实际文件核对哈希和归属。

检查命令沿用输入时间基，避免把可变帧率视频转换到较粗的帧率时间基后，在空输出阶段产生重复时间戳。它仍逐帧解码，不丢帧或补帧来消除报错；原视频字节保持不变。时间基参数说明见 [FFmpeg 文档](https://ffmpeg.org/ffmpeg.html#Advanced-options)。

## 保留手机原件

系统可能在仍采集时就发布可读的 MP4。停止流程会先核对本次所有权、确认采集结束，再接收和校验文件；这个约束同时适用于有、无持久日志的调用。出现其他录屏、停止响应丢失或结束等待超时时，不会因容器有效就删除媒体，也不会重发切换命令。

需要对照导出文件与手机媒体时，可以开启诊断选项：

```powershell
$env:MAESTRO_HARMONYOS_RECORDING = 'huawei-system'
$env:MAESTRO_HARMONYOS_RECORDING_RETAIN_MEDIA = 'true'
# 使用正常 runner 执行一个有明确 stopRecording 的短流程。
```

此选项默认关闭，只接受 `true` 或 `false`，并且要求持久设备会话。启用后，正常停止也保留手机上的本次媒体，并返回需要恢复的状态；下一会话会被阻止。它是诊断工具，不能放进预期全部成功的常规批次。

持久会话在首次录屏操作前登记资源：唯一文件名、会话所有者、远端临时路径、启停意图、捕获结束事实、媒体 URI 与原件哈希。原件保存在该会话目录下的 `recording-originals/`，索引为 `recording-resources.json`。普通持久会话也保存原件，以覆盖删除设备媒体后、清理状态尚未写入时进程退出的情况。单份归档最多 1 GiB；没有总量自动回收机制，长期运行前需检查磁盘空间。未核验的失败原件不能当作临时缓存删除。

已确认结束、非空且接收完整的导出文件，即使 MP4 结构校验失败，也会先归档原始字节，再继续原有的有限等待与校验。坏文件不会写入正常录屏输出，也不会使停止操作成功；若随后取得有效版本，两版都保留。停止预算内的多次坏导出可能产生内容相同的归档，当前不去重，应为失败调查预留磁盘空间。

这不覆盖零字节、接收失败或未确认结束。归档本身失败或剩余时间不足时，设备媒体继续保留、清理保持未知；已填写 URI 不能代替完整原件。结构校验通过后的 H.264 帧错误仍需独立的完整解码检查。

恢复重新导出时，`mediatool` 不会覆盖已存在的目标文件。恢复入口先检查本资源已登记的远端临时文件：存在时完整接收，核对接收前后尺寸和本地字节；如果它是尚未归档的版本，先保存原件，本次保持未知。后续恢复只有确认这些字节已有完整归档，才可删除临时文件并重新导出比较。未归档的零字节文件、短收、不稳定尺寸或文件类型不明时不会覆盖它；旧版已登记且核验完整的零字节归档仍可按原字节比较、清理，不因此被认定为有效视频。手机媒体已经不存在时，也要先处理这个残留文件，不能直接标为清理完成。

删除与导出进入原会话的命令日志；响应丢失或仍有原生子进程未结束时，停止后续资源操作，下一次恢复先核实命令和进程状态。新导出的内容匹配后，才进入媒体删除和设备释放流程。所有本地原件版本继续保留。

诊断结束后移除环境开关，只影响后续新录制，不会清除旧会话：

```powershell
Remove-Item Env:MAESTRO_HARMONYOS_RECORDING_RETAIN_MEDIA
```

## 通过已有恢复入口解除占用

使用现有 v2 `agent.recover`，传入错误详情中 `recoverySessionId` 指定的原会话。调用及报告校验见[智能体客户端示例](../examples/agent-client/README.md)。不能用 runId、attemptId 代替设备会话 ID，也不能通过删除占用记录恢复使用。

恢复先取得原设备锁和会话日志锁，核实旧进程及已登记命令结束。已经确认启动、但尚未持久登记结束的录屏，可以补查当前状态：连续两组进程、采集服务和唯一文件名查询，都须确认没有活动采集、没有其他录屏进程，并指向相同的本次媒体 URI。条件满足才登记结束。缺少启动确认时通常保持阻塞；仅当原会话记录明确绑定该资源的锁屏拒绝错误 `10106102`，且两次独立检查均确认无录屏进程、无采集、无同名媒体和无临时导出文件，才登记拒绝启动并允许后续清理。此分支不发送录屏启停切换命令、不伪造视频原件，证据留在资源登记 v2 和恢复快照中。

从未归档的资源先保存完整原件：优先接收原登记路径上的文件；只有确认该路径不存在才导出到同一路径，避免覆盖中断时留下的字节。首次归档返回 `RECORDING_ARCHIVED_RECHECK_REQUIRED`，仍不允许接管。下一次显式恢复独立导出、核对大小和 SHA-256，再决定是否删除手机媒体与临时文件。

如果媒体内容变化，保留旧版与新导出的原件，本次保持未知；后续显式恢复仍需重新比对。已经登记的原件缺失或哈希不符时，不能用重新下载来覆盖这个缺口。无法确认结束、其他录屏正在运行、命令回执不完整或前次原生进程未结束时，同样保持未知。每次资源操作前后都会检查日志状态；出现未确认命令或进程后，不能再处理其他资源。

显式恢复共用 30 秒设备检查预算，包含补查、接收、核验和清理。预算不足时保存未知报告，保留原件与占用；它不循环调用自己。大型视频可能需要后续显式恢复，且不能保证在单次预算内完成。客户端等待方式见[恢复协议](agent-protocol.md#51-v2-受控恢复)。

录屏恢复凭据使用内部版本 2，并引用 `recoveries/<recoveryId>-recordings.json` 的不可变资源快照和哈希。外部 agent 协议版本不变。消费者需要同时核对该快照，不能只检查 `complete` 字样。恢复只证明资源可以移交，不修改原执行结果或为旧视频补写“通过”。

正文断言与录屏关闭同时失败时，执行结果保留正文错误，清理状态及 `DEVICE_RECOVERY_REQUIRED` 放在独立的 cleanup.errors 中。读取报告时需同时检查两者：`ASSERTION_FAILED` 说明正文失败，不能据此判断设备已释放。已有 cleanup unknown 不会因为随后写入终态而变成已确认的清理结果。
