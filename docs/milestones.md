# 课题 11 开发里程碑计划

版本：v1.2｜更新日期：2026-10-29｜计划交付：2026-12-23（北京时间）

技术路线见 [开发技术方案](technical-plan.md)，测试范围和通过率计算见 [验收计划](acceptance.md)。以下日期为开发安排，实际完成情况随仓库进展更新。

## 当前进度

已提前完成 Windows 构建、HarmonyOSDriver 和 CLI 会话接入。一台真机已通过标准 YAML 输入、断言、截图及滑动后重新定位；单设备批量执行 2/2 通过，PowerShell 运行脚本的中文和引号参数回归已通过。实验性的 Huawei 系统录屏后端默认关闭，正常流程录屏及严格全帧解码已通过；失败流程自动收尾已验证，短视频出现过尾部解码错误，原样复跑通过，偶发原因尚未查明。

VSCode 操作录制扩展已提供 0.1.0 VSIX，主机单元测试和 ExtensionHost 检查通过；在 VSCode 1.140 与现有 ALN-AL80 / API 26 真机上，真实面板的 8 步录制、YAML 保存及 CLI 回放通过。逐台验证脚本也已在同一设备执行 1/1 通过。

当前仍为 **M3 部分完成**，不代表 M0～M3 的全部完成标准已满足。活动约定示例、20 轮稳定性及第二台设备兼容测试未完成。报名确认日期、活动要求的仓库权限和验收口径仍待登记。原计划日期保留，已有驱动与录屏结果见 [2026-10-28 进展记录](progress/2026-10-28.md)。

## M0：仓库与方案（10-28 至 10-30）

整理技术方案、开发计划、验收清单、许可证和固定上游版本。按活动组指引登记报名时间、仓库权限，并确认官方示例、必需命令、录制辅助形式和成功率口径。

- **交付**：本次方案与计划、上游版本记录、活动事项处理记录。
- **完成标准**：材料已入库，活动启动事项已处理。当前仓库、初始文档和本机工具已就绪；未完成的活动事项继续保留，不妨碍先做技术验证。

## M1：构建与真机最小流程（10-31 至 11-06）

先确认固定上游在 Windows 上的构建路径。除了 JDK，还要检查 npm/MCP viewer、simulator-server 资源下载及 iOS 模块依赖对 CLI 构建的影响，记录必要的构建参数或调整。

连接并授权手机，登记型号和系统版本。在本阶段前半段验证布局字段、id/文字定位、滚动后定位、中文输入，以及录屏启停和视频拉取。随后接入 HarmonyOSDriver，使标准 YAML 通过 Maestro 原有执行层完成启动应用、点击、输入、断言和截图。

- **交付**：构建说明、最小驱动补丁、YAML 用例、运行日志、布局与截图；中文输入和录屏的真机验证结果。
- **完成标准**：固定上游可构建，最小 Flow 在真机通过。布局、输入或录屏没有可行实现路径时立即记录影响并调整安排，不留到 M3 再排查。
- **依赖**：仓库基线已准备，手机可连接。手机未就绪时可先做构建和接口梳理，真机部分不能标为完成。

## M2：命令与流程适配（11-07 至 11-20）

补齐约定的点击、滑动、返回、输入、选择器和断言；验证 Flow 复用、参数、条件及约定的 JavaScript 用法。处理页面等待、超时、断连和安全重试，分别保留首次失败与重试结果。记录每项命令的支持情况，验证补丁能重新应用到固定上游。

- **交付**：驱动补丁、命令覆盖清单、Flow 示例和测试记录、支持范围说明。
- **完成标准**：约定命令与流程有实际测试结果；未实现能力明确报错；从固定上游应用补丁后能构建并重现核心用例。
- **依赖**：M1 最小 Flow 已通过，布局与坐标转换可用。

## M3：录制、插件与批量执行（11-21 至 12-04）

把视频录屏接入测试流程，处理停止、文件拉取和异常退出。完成 VSCode YAML 高亮、设备截图、节点点选及操作生成 YAML，再接通 CLI 批量执行和标准报告。记录取消执行、无设备和部分用例失败时的行为。

- **当前状态**：部分完成。单设备批量 2/2、矩阵工具单设备 1/1 通过；VSCode 0.1.0 已打包，真实面板的 8 步录制、保存与回放通过，回放后会话释放且步骤保留。`huawei-system` 正常录屏及失败收尾已实测，短视频偶发尾部解码错误仍待查，后端保持实验性且默认关闭。第一版插件只录制插件内操作，多设备分片尚未支持。
- **交付**：可播放的运行视频、可安装的 VSCode 扩展、生成的 YAML 示例、批量执行报告和使用说明。
- **完成标准**：插件生成的 YAML 能保存并由 CLI 回放；报告与实际结果、退出码一致；视频能对应到测试步骤。视频录屏和操作录制辅助分别检查。
- **依赖**：M2 驱动可稳定调用；M1 已验证录屏路径；操作录制辅助形式已与活动组明确。若要求捕获手机上的任意手工操作，需要重新评估实现与工期。

## M4：稳定性测试（12-05 至 12-16）

先用完整套件预跑并修复问题，再固定示例、驱动、插件、脚本、设备环境和重试策略，按约定口径运行 20 轮。逐轮记录失败步骤、原因和产物，分别统计首次与重试后的通过率。

- **当前状态**：尚未开始正式 20 轮统计。逐台验证工具已具备环境、版本、轮次和结果汇总；已有单次 Flow、2/2 批量及矩阵单设备 1/1 结果不计作稳定性验收，第二台设备仍未实测。
- **交付**：版本与环境记录、20 轮结果、失败分析、日志、布局、截图和约定视频。
- **完成标准**：按活动组确认口径达到不低于 95% 的通过率，即 20 轮至少 19 轮通过；失败和人工介入如实保留。修改驱动、用例或策略后重新建立该版本的正式记录。
- **依赖**：M2/M3 必需能力已完成；官方示例、场景、初始状态和统计口径已确认。具体计算规则见 [验收计划](acceptance.md)。

## M5：交付与申请验收（12-17 至 12-23）

整理源码、补丁、扩展、用例、测试记录及使用和开发指南。用干净检出按文档完成构建和代表性用例回放，核对是否缺少文件或依赖个人路径。按活动组流程提交材料，记录版本、提交时间和反馈。

- **交付**：完整交付清单、可复现构建与运行说明、测试材料、已知限制和验收申请记录。
- **完成标准**：交付清单逐项有对应文件或测试结果，干净检出可以复现，申请已按要求提交。申请提交和活动组验收通过分别记录。
- **依赖**：M4 达标并保留完整记录。上游 PR 合入和应用市场发布不作为额外交付条件。

## 进度更新与延期处理

每周三更新一次：10-28、11-04、11-11、11-18、11-25、12-02、12-09、12-16、12-23。至少每 7 个自然日在 `docs/progress/` 留下完成内容、提交或测试结果、阻塞和下周安排；阶段完成以实际结果为准。

出现延期时记录原因、影响阶段、处理办法和预计日期，保留原计划。优先完成约定能力与正式测试，可推迟额外平台、额外系统版本和界面美化；涉及必需能力或交付日期的调整，与活动组确认后更新。

活动“报名成功后 3 个自然日内”的起算点采用活动组实际确认日期，登记后核对材料提交时间，不使用建仓日期代替。
