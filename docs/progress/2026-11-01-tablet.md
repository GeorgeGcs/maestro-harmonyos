## 重连后的恢复检查

平板重新连接后，普通恢复找回一条命令的完成凭据，未确认命令从两条降为一条。剩余命令的参数摘要唯一对应于已登记布局文件的 `rm -f`；只读检查未找到它的凭据目录，布局文件仍存在。HDC 连接恢复不能证明该旧命令已经结束，会话继续保持 `unknown`，没有开始残留故障注入或新的 UI 测试。

核查同时发现维护恢复与路径保留策略不兼容：旧维护入口要求临时资源清单为空。此次补充仅允许原会话登记的布局 JSON 和截图 PNG，取得顺序重启证据后按精确路径清理，并同步扩展 CLI 与 Node 的完整清理范围核验。录屏、其他临时文件、链接或未登记内容仍拒绝接管；原日志中的命令结果与资源登记保持不变。

主机复现还确认，旧实现重新打开日志时会改变临时文件数组的顺序。现在按原数组顺序恢复集合，并拒绝重复路径，防止维护核验将反序列化重排误判为日志被修改。维护工具迁移代码同时改为局部保存可空引用，解决增量编译时的智能类型转换错误。

## 不重启路径的独立验证

2026-11-02，转而验证“先占住旧命令执行前必须创建的操作目录”。真实包装器先执行互斥 `mkdir`，成功后才运行原命令。恢复先创建目录时，迟到的旧包装器会在原命令执行前退出；旧命令先创建时，恢复必须拒绝。目录必须保留，删除后旧命令可以重新执行，负向对照已确认这一点。

主机原型 24 项、平板独立文件系统原型 10 项通过，包括 20 次主机竞争、4 次设备竞争、创建目录后写标记前失败、符号链接拒绝及独立新代际执行。主机也用产生本次阻塞会话的原冻结 CLI 通过同样 24 项；数量不重复累加。首次平板探针因输出回车符导致字符串比较失败，修正后在新目录复测；首次探针自己的目录已核对并清理。

原型测试持有同一设备锁，只进入随机新目录；原占用和恢复日志前后逐字节不变。没有重启或操作应用，也没有解除真实会话。它证明了窄范围阻挡机制。随后接入保留目录登记、恢复事务及 CLI/CI 核验，入口与边界见[清理恢复说明](../cleanup-fence-recovery.md)。
