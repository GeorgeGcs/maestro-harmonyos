## 第一批代码

代码放在固定上游的 `maestro-client` 模块，通过 `patches/maestro/0001-harmonyos-host.patch` 交付：

- `HdcClient`：设备发现、显式选择、设备 shell 调用和文件拉取。
- `ProcessHdcCommandRunner`：独立参数启动、双输出流读取、输出大小限制、超时与中断处理。
- `UitestLayoutParser`：将 UITest 布局转换为真实 `TreeNode`，映射 id、文字、坐标和控件状态。
- `HierarchyReader`：按固定设备读取新布局，拉取临时文件、校验和解析，并处理失败及清理。
- `HarmonyOsHostCli`：开发用设备查询入口，不承担 YAML 执行。

布局格式依据固定版本的 OpenHarmony UITest 源码。测试使用合成布局和模拟 HDC，未将这些结果当作真机兼容证明。

新增补丁回放、主机测试脚本，以及 `host-tests` 独立构建入口。主机测试直接编译同一份代码和必要的上游类型；完整客户端测试额外检查真实 Maestro 选择器和坐标转换。

### 本轮失败及修复

- 初次设备启动因锁屏返回 `10106102`，但 HDC 主机进程退出码为 0。用户解锁后启动成功；驱动现在同时检查远端返回码和 `aa` 成功消息。
- 首次真实 CLI 在点击前等待布局超时。原实现将剩余时间平均分给布局、传输和清理，第二次布局读取只获得约 1.1 秒。改为布局和传输共用剩余预算，清理单独最多 2 秒；等待预算耗尽返回未稳定，命令错误、清理失败和中断继续报错。原失败日志保留在 `artifacts/device-probe/cli-run-20261028-202818/`。
- 源码复核发现 UITest 输入失败也可能返回 0。现要求输入命令明确返回 `No Error`，并在主机和 YAML 集成层补充失败回归；该成功消息已在真机核实。
- 第一轮 YAML 集成的截图文件已生成，但测试错误地要求 manifest 逐张列出截图。按上游截图集合语义修正检查，仍验证目录归属、文件存在和 PNG 尺寸。原失败报告保留在 `artifacts/verification-initial/`。
