# 2026-11-01 开发验证

本次继续使用同一台真机和已签名的 ComponentCollection，验证完整场景、同会话批量执行与录屏。以下是开发运行，未执行固定版本的 20 轮稳定性测试，也不合并不同构建的结果计算通过率。

## 场景预跑

按钮、弹窗、文本输入、滑动后重新定位四条 Flow 已分别执行通过，清理均为 `complete`。输入页的计数文字覆盖输入框中部，直接点中心不能稳定取得焦点；用例改用标准相对坐标点击控件内部上方，并在输入前断言 `focused: true`。源码、断言和使用方式见[场景说明](../../examples/component-collection/README.md)。

首次按钮预跑曾因 10 秒收尾预算不足而保留 `unknown`；正常关闭预算调整到 30 秒后单条预跑通过。首次输入断言失败及这次收尾未知均保留原结果，没有用后续成功覆盖。

## 批量清理修复

把四条普通 Flow 的目录交给一次 CLI 调用，UI 结果为 4/4 通过，但整批因清理超时退出 1。该会话累计 640 条操作记录；旧实现逐目录启动删除命令，30 秒内只确认清理了其中 160 条，整体保持 `unknown`。

修复后，每组先核对日志登记的精确目录，再集中删除指定标记和空目录，减少远端进程数量。仍使用原清理预算、命令长度限制和逐批确认；不递归删除，不删除额外文件，未确认的批次仍可恢复。

用新 CLI 对原会话显式恢复，约 7 秒完成剩余清理，独立校验恢复报告后允许接管；原执行结果哈希未变。普通批次的 95 个步骤、21 份引用文件核验通过，无缺失证据。恢复完成只说明设备可交接，不改变原批次的 `unknown`。

核对了 111 个步骤、25 份引用文件，无缺失证据；录屏诊断报告完整，四段视频均能关联到本次输出。FFmpeg 对原件逐帧解码通过，无 error 级诊断，输入哈希保持不变，且与报告中的视频输出哈希一致。解码结束时间分别约为 131、193、129、140 秒；每段第 60 秒画面抽查均为相应应用页面。抽查不能替代逐步骤的画面审阅，音轨也不在解码检查范围内。

这次通过不代表历史短录屏尾部解码问题已修复，系统录屏仍默认关闭、标为实验功能。还需固定版本的重复稳定性验证，以及当前 CLI 与 VSCode、通用 CI 入口的联测。

## 配置和主机验证

新增 `MAESTRO_HARMONYOS_RECORDING_MAX_SECONDS`，接受 1～600 的整数，默认仍为 180 秒，也不会自动开启录屏。弹窗场景正文的预跑耗时超过三分钟，本组录屏设为 300 秒；整个 runner 的超时另设为 1200 秒。

CLI 与 VSIX 已从 `f285dc8` 完成使用声明缓存的隔离构建。随后仅修正 Windows 下实际 shell 测试的命令传递方式和工具路径，测试源码提交为 `0f0e723`，已安装 CLI 未替换。104 项相关测试通过，无失败或跳过，覆盖恢复日志、维护恢复、会话释放和录屏时长配置。实际 shell 测试覆盖正常清理、目录已不存在、额外文件和非目录路径。

这不是整个 Maestro 仓库的全量测试。设备身份、签名、原始日志及视频保留在本地，不随公开文档提交。
