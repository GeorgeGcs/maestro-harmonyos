# HDC 诊断与最终清理核验

## 问题

11 月 4 日 21:30 开始的完整套件重复批次，前 3 轮通过，第 4 轮在弹窗结束后的回程导航中出现 HDC 超时，后续 16 轮未执行。原记录保持不变，不能作为 20 轮稳定性通过的依据。

当时记录了约 5 秒的执行超时和约 2 秒的临时清理超时。随后会话关闭实际完成清理，生成了 clean gate 和完整回执，但报告仍把早先的附带清理错误写成最终 `cleanup=failed`。CI 因此保留设备占用。旧日志也缺少命令类别和阶段信息，无法确定超时发生在读取布局、接收文件还是输出收取阶段；HDC 延迟的底层原因尚未确认。

## 修改

- HDC 调用记录安全类别、调用编号、预算、阶段耗时、退出码、输出收取和异常终态，并关联已有资源日志的操作与主机调用编号。详见[日志使用方法](../setup.md#定位-hdc-超时)。
- 新日志不包含参数、设备标识、输出正文或异常消息；专用日志标记只进入文件捕获，避免混入 verbose 命令的 JSON 输出。日志异常不替换执行结果。
- CLI 只在当前会话正常返回、驱动关闭和持久化清理成功后确认最终清理。早先的附带错误保留在 `error.details.suppressedErrors`，执行失败本身不变。旧会话确认、普通状态赋值、关闭异常及恢复阻塞不能获得这一确认。
- CI 和验证计划分别核对执行与资源释放。执行 `unknown` 仍返回非零并停止后续轮次；正常退出、完整输出、`cleanup=complete`、当前 clean gate、清理回执和证据摘要均有效时，才允许释放设备。缺失或矛盾的凭据仍阻止释放。

本次没有调整 YAML、超时阈值、重试策略或统计口径。旧 CLI 和旧批次均保留，新 CLI 构建到独立目录。
