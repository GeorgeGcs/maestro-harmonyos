# 2026-11-05 布局查询超时与平板恢复

## 问题与修改

平板补充批次第 6 轮的页面流程已完成，但有一条布局导出命令未取得远端完成凭据，整轮收尾为 unknown。原记录保留在[平板验证](2026-11-05-tablet.md)，不改写为通过。

日志显示：5 秒页面稳定等待末尾仍发起了预算仅 58 ms 的布局查询。查询超时后，删除临时文件成功，驱动将异常当作“尚未稳定”继续执行；远端操作却仍留在恢复日志中，直到最后释放设备才触发隔离。正常布局调用约需 1.7～1.8 秒。前五轮同样有 31 次布局查询超时，但后来都取得了完成凭据；没有逐轮变慢的证据。

本次修改：

- 等待窗口只控制是否开始下一次采样，单次查询保留完整命令预算。后续采样参考同一次等待中上一份样本的耗时，窗口尾部不足就返回未稳定。
- 已派发的布局或截图查询超时向上报错，不再以临时文件删除成功判断可以继续。该驱动实例拒绝后续页面请求，录屏关闭及会话收尾仍可执行。
- 扩展原有不重启恢复：对精确匹配登记文件的布局导出，使用原子目录占位阻挡迟到旧命令。长会话按根目录和文件清单分步核验，CLI、客户端、CI 归档和新会话使用同一凭据规则。

未确认的旧命令具体停在传输或包装器的哪一步，仍没有足够证据。修复不会根据客户端退出或文件不存在直接宣称远端完成。

## 平板现场恢复

19:05（北京时间），使用修复后的独立 CLI，通过 `harmonyos-cleanup-recovery` 完成真实恢复：

- 原会话共 562 条操作、268 个登记文件，只有一条布局导出未确认。
- 取得 `prevented_before_dispatch` 凭据，`handoffReady=true`；阻挡目录保留，原结果仍为 unknown。
- CLI 退出码 0；客户端与 CI 独立核验确认可以释放，核对 63 份文件。
- 原 journal 和原收尾回执字节不变。外层 CI 占用通过正式核销入口解除。
- 未重启电脑或平板，未删除隔离记录来绕过核验。

该结果验证了本次实际 HDC 对分步长命令的执行和回执链路。恢复机制及适用范围见[恢复说明](../cleanup-fence-recovery.md)。
