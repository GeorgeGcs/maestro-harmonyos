# 2026-11-03 HMOS 代码工坊稳定性验证

在官方 HMOS 代码工坊的 Button 详情页，新增的[按钮样式 Flow](../../examples/hmos-code-lab/flows/04-button-style.yaml)完成一次手机开发验证。它切换 `Emphasized → Textual → Emphasized`，每次检查当前样式，最终恢复初始状态。原[按钮 Toast Flow](../../examples/hmos-code-lab/flows/01-button.yaml)的短时提示断言仍未通过；两个 Flow 不能合并记作同一结果。

## 20 轮首次执行

以固定应用包、Flow 和 CLI 文件准备了手机上的 20 轮执行。前 3 轮 `passed / cleanup=complete`。第 4 轮的 UI 步骤通过，但一条已返回的 HDC 本机调用仍有子进程退出状态未确认，整轮为 `unknown`。执行器按设备隔离规则停止，后 16 轮没有运行。该批次不能计算为 20 轮通过，也不达到交付稳定性条件。随后使用 `agent.recover` 核对旧会话，确认相关本机进程终止、设备命令与临时文件无待处理项，再释放设备；原第 4 轮结果仍为 `unknown`。

## 收尾修复与短跑

HDC 客户端返回时，其控制台子进程可能尚未退出。主机侧 50 次只读 HDC 调用观察到短暂存在的控制台子进程；这说明有退出时序窗口，但尚不能证明首次批次那条未确认进程就是同一种子进程。

正常会话关闭现在可在原有 30 秒收尾预算内，用最多 10 秒复查**已登记的本机进程身份**。进程确实退出才登记完成；进程持续运行、身份缺失或预算耗尽仍返回 `unknown`，继续阻止接管。显式恢复规则不变。客户端恢复与录屏资源回归测试、CLI 会话与锁屏拒绝录屏恢复测试通过。

用修复版 CLI 在同一手机和同一前台页面运行 10 轮只读准备 Flow：10 轮均 `passed / cleanup=complete`，无录屏、无失败重试。该短跑只诊断会话收尾，不计入官方 Button Flow 的 20 轮；正式批次需用重新冻结的完整 CLI 单独执行。
